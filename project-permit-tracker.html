East Texas Permit
Tracker

Intro

A team database project

During my Spring semester this past year, my Database Design class had us working in a team to design a MySQL database. We went with UT Tyler's Hibbs Institute to track building permits across East Texas.

Role:
Database Designer
Tools:
MySQL, ER diagrams
Timeline:
Spring semester
Team:
Anna Arseienko
Alexis McGowan
Drew Lamonica
Kevin Sheja Jabo

Context

Why permits matter

The Hibbs Institute for Business & Economic Research is part of UT Tyler's Soules College of Business. It studies the East Texas economy and publishes research that local businesses, city leaders and economic development groups use to make decisions. Tracking permits well helps the Institute see where the region is growing, what kind of construction is driving it, and who is doing the building.

Problem

One messy spreadsheet

The raw data we received was one big spreadsheet where every row retyped the owner, business, address and contractor. Because of this, the same company could show up under different spellings, and fixing one detail meant hunting down every row it appeared in.

Process

Clean, map, normalize

In the beginning of the project, we decided to clean the CSV and then build the seed data from it. The design from there centers on the permit table, and every other table describes something a permit points to. We mapped all of this in an ER diagram before writing any code, then normalized it to Third Normal Form and built rules into the database itself.

Solution

A working database

The result is a working MySQL database. After building it, we loaded real Tyler-area permits from 2024-2025, and the database now answers the Institute's questions with a single query.

Reflection

Plan before the SQL

I learned that a lot of the work is deciding what belongs in which table before writing any SQL. Once we had the ER diagram, I knew what every table was supposed to hold, so the code was mostly just following the plan we already made.

Working with real permit data made it feel different from a normal class assignment. The messy spellings and repeated names were an actual problem someone has to deal with, and normalizing the data is what fixed it. Now a detail only lives in one place, so changing it is one update instead of a hunt through every row.

Doing this as a team of four meant we had to agree on the design early, and having the diagram to point at made that a lot easier. If I did it again, I would still spend most of the time on the design up front, and I would like to build more queries and a dashboard on top of it.
